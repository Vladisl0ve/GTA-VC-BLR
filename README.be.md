# GTA GXT Editor

**Мова:** [English](README.md) · Беларуская

Windows-рэдактар тэкставых рэсурсаў GTA III і GTA: Vice City, адаптаваны для працы над беларускімі перакладамі. Прадвызначаная мова інтэрфейсу — англійская; таксама даступная беларуская.

## Дакументацыя

Гэты README — галоўная старонка дакументацыі праекта. Падрабязныя дапаможнікі:

- Мовы, кадзіроўкі і карыстальніцкія мапінгі — якія моўныя табліцы ўбудаваныя для GTA III і Vice City, як працуе аўтавызначэнне і як замяніць табліцу сімвалаў уласнай: [English](docs/languages-and-encodings.md) · [Беларуская](docs/languages-and-encodings.be.md).

## Тэхналогіі

- .NET 10 LTS і C# 14;
- WPF/XAML з сістэмнай тэмай Fluent;
- MVVM на аснове `CommunityToolkit.Mvvm` 8.4.2;
- MSTest 4.3.2 і Microsoft Testing Platform;
- nullable-спасылкі і аналізатары .NET у стылі SDK.

## Запуск праекта

Патрэбны .NET SDK 10.0.302 або навейшы патч-рэліз галіны 10.0.

```powershell
dotnet restore "GTA GXT Editor.slnx"
dotnet build "GTA GXT Editor.slnx" --configuration Release
dotnet test "GTA GXT Editor.slnx" --configuration Release
dotnet run --project "GTA GXT Editor.csproj"
```

## GXT, TXD і мапінг сімвалаў

Да адкрытага GXT можна далучыць не больш за адзін TXD. Разам яны ўтвараюць пару з уласным профілем адпаведнасці паміж Unicode-сімваламі і кодамі ў дыяпазоне `0x20–0xFF`: байт у GXT выбірае ячэйку атласа TXD, а профіль апісвае, які сімвал знаходзіцца ў гэтай ячэйцы.

Рэдактар мапінга паказвае атласы `font1`, `font2` і `pager`, а таксама код і прызначаныя сімвалы кожнай ячэйкі. У ім можна:

- прызначаць і ачышчаць сімвалы, а таксама выбіраць пераважны код для кадавання;
- імпартаваць кананічны `.gxtmap.json`, скарочаны JSON і стары тэкставы слоўнік;
- экспартаваць кананічны `.gxtmap.json`;
- ужываць убудаваны беларускі прэсет з `Ё/ё`, `І/і` і `Ў/ў`, загружаны з кананічнага рэсурсу;
- аналізаваць адсутныя сімвалы, непрызначаныя байты, канфлікты і частату выкарыстання;
- інтэрпрэтаваць зыходныя байты без змянення GXT або транзакцыйна перакадзіраваць бягучы Unicode-тэкст для TXD.

Фарматавальныя канструкцыі `~...~` заўсёды кадуюцца як службовы ASCII. Адзін код мае аднолькавае значэнне для ўсіх шрыфтоў у далучаным TXD; змяняецца толькі выява гліфа. Рэдактар не змяняе пікселі або размяшчэнне гліфаў.

Кананічны профіль выглядае так:

```json
{
  "version": 1,
  "mappings": [
    {
      "character": "А",
      "codes": ["0x41"],
      "preferredCode": "0x41"
    }
  ]
}
```

Адзіная ўбудаваная крыніца беларускага мапінга знаходзіцца ў
`Assets/ViceCity/belarusian.gxtmap.json`. Яна ўбудоўваецца ў праграму і адначасова
капіруецца ў выходны каталог для выкарыстання з GXT/TXD. Профіль задае мэтавую
раскладку беларускага `fonts.txd`: захоўвае ASCII-псеўданімы 1C, выкарыстоўвае
`І = 0x49` і `і = 0x69`, а слоты рускага `И/и` аддае пад `Ў = 0x86` і
`ў = 0x9D`. Былыя слоты `Ъ/ъ` зарэзерваваныя для `Ё/ё`:
`Ё = 0x96`, `ё = 0xAF`.

GXT, створаныя папярэднімі версіямі праекта, распазнаюцца асобна. Рэдактар умее
чытаць старую неперарыўную схему `0x80–0xBF` і прамежкавую схему са слотамі
`І = 0x86`, `Ў = 0x91`, `і = 0x9D` і `ў = 0xA8`. Каб выкарыстаць такі файл у
гульні, перакадзіруйце яго актуальным убудаваным прэсетам, а не проста захоўвайце
без змен.

Каманды **«Адкрыць з мапінгам…»** і **«JSON → GXT з мапінгам…»** прымаюць
кананічны `.gxtmap.json`, скарочаны `.json` накшталт `{ "А": "0x80" }` і стары
слоўнік `.txt`. Яўна выбраны файл мае прыярытэт над убудаванай кадзіроўкай.

Пры асобным экспарце GXT або TXD праграма таксама прапануе захаваць профіль
`.gxtmap.json`. Пры замене TXD профіль застаецца неправераным чарнавіком; пасля
выдалення TXD ён працягвае дзейнічаць як карыстальніцкая кадзіроўка GXT.

## Праекты BYX

BYX v4 — самадастатковы ZIP-кантэйнер з GXT, неабавязковым адзіночным TXD,
профілем пары, метаданымі перакладчыка і кантрольнымі сумамі SHA-256. Праект Vice
City таксама можа змяшчаць профіль інсталятара Windows і яго бінарныя рэсурсы пад
бяспечнымі архіўнымі назвамі на аснове GUID. Агульны распакаваны памер абмежаваны
512 МБ, а профіль інсталятара — 512 файламі.

Праекты BYX v3 працягваюць адкрывацца з пустым профілем інсталятара і пры наступным
захаванні запісваюцца як v4. BYX v1/v2 і версіі, навейшыя за v4, адхіляюцца.

Падтрымліваюцца PC TXD RenderWare D3D8/D3D9: PAL4/PAL8, распаўсюджаныя
8/16/24/32-бітныя растры, DXT1 і DXT3. TXD для PS2, Xbox і мабільных версій
адхіляюцца да змянення адкрытага праекта.

## Экспарт інсталятара Windows

Для праекта GTA Vice City з далучаным TXD выберыце **«Экспартаваць як → Інсталятар
Windows…»**. Каб загадзя падрыхтаваць і захаваць яго файлы, скарыстайце панэль
**Інсталятар Windows** пад элементамі кіравання TXD і захавайце праект як BYX.
Праект можа захоўваць няпоўны чарнавік профілю пасля выдалення часткі або ўсіх
файлаў. Для экспарту патрабуюцца `BelarusianLanguage.asi` і набор SilentPatch з
`SilentPatchVC.asi`, `SilentPatchVC.ini` і васьмі патрэбных файлаў IPL. Файлы з
BYX застаюцца выбранымі пры наступных экспартах. ASI Loader і адвольныя дадатковыя
файлы ў інсталятар не дадаюцца.

Афлайн-экспарт стварае адзін беларуска-англійскі `Setup.exe` убудаваным Inno Setup
7.0.2 x86. Інсталятар заўсёды запісвае `TEXT\BELARUS.GXT`, `MODELS\FONTS.TXD` і
`BelarusianLanguage.asi`; SilentPatch — асобны, першапачаткова выбраны кампанент.
Арыгінальныя файлы шрыфту/IPL люструюцца ў `_BelarusianModBackup\<ProductId>`.
Транзакцыйны стан, ліцэнзіі, канфлікты і дэінсталятар жывуць у
`_BelarusianMod\<ProductId>` у папцы гульні. Выбраная папка выкарыстоўваецца без
змяненняў і не мусіць змяшчаць `gta-vc.exe`. Дакладны кантракт апісаны ў
[дакументацыі экспарту](docs/windows-installer.be.md).

## Магчымасці GXT

Праграма чытае і запісвае файлы GXT GTA III/Vice City і падтрымлівае ўбудаваныя
і карыстальніцкія табліцы сімвалаў, пошук, дадаванне, рэдагаванне, выдаленне і
імпарт адсутных ключоў, а таксама пераўтварэнне GXT у JSON і назад.

Для GTA Vice City убудаваныя метаданыя парадку праходжання аўтаматычна дадаюць да
запісаў назвы місій і гульнявых блокаў, кантэкст і парадак з'яўлення. Кананічны
слой даступны толькі для чытання, не капіруецца ў BYX і не замяняе карыстальніцкія
каментарыі перакладчыка. Калі праект BYX мае ўласныя ўваходжанні для запісу, яны
маюць прыярытэт над убудаванымі метаданымі.

Табліцу можна фільтраваць паводле тыпу і назвы блока і пераключаць паміж парадкам
праходжання і зыходным парадкам GXT. Першы файл, дададзены праз
**«Крыніца/параўнанне…»**, лічыцца англійскай крыніцай і паказваецца ў табліцы,
інспектары і рэдактары запісу.

Каментарыі перакладчыка захоўваюцца ў метаданых праекта BYX. Пры даданні
каментарыя да звычайнага GXT каманда захавання прапануе стварыць праект BYX;
асобны экспарт GXT застаецца даступным. Імпарт і экспарт каментарыяў выкарыстоўваюць
фармат `GXT_COMMENTS` v1 і змяшчаюць бягучы тэкст для выяўлення несупадзенняў.

Беларуская мова падтрымліваецца ўбудаванымі кадзіроўкамі абедзвюх гульняў,
уключаючы `Ё/ё`, `І/і` і `Ў/ў`. Поле JSON `"language": "be"` выбірае беларускую
кадзіроўку GXT без эўрыстычнага вызначэння. Мова можа прапанаваць прэсет, але
ніколі не замяняе профіль мапінга пары GXT + TXD аўтаматычна.
